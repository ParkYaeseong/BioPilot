## 실행과 현재 확인 범위

프로젝트 루트 PowerShell에서 기존 환경을 사용합니다.

```powershell
.venv/Scripts/python.exe -m streamlit run app/bench.py --server.port 8522 -- --state-dir .runtime/bench --max-runs 3 --max-requests 4
```

주소는 http://127.0.0.1:8522/ 입니다. 예전8523북마크는 이 주소로 안내합니다.
기존 `app/viewer.py`는 별도 읽기 전용 도구로 보존하지만 통합 앱을 쓰기 위해 두 프로그램을
오갈 필요는 없습니다. 현재 PC의 핀을 검증한 로컬 ESM 설정은
`.cache/local_esm150_verified.env`이고, Meta 인증정보는 원래 신뢰된 로컬 설정에서만 읽습니다.
설정·가중치·인증정보는 Git에 올리지 않습니다. 다른 PC의 새 설치는 별도 검증이 필요합니다.

실제 업로드 FASTA 요청의 새 실행이 완료됐습니다. 실제 모델은 `muse-spark-1.3`, Meta
요청3회, 로컬 CPU ESM-2 150M, 전체 기준 위치32의 후보19개, 기록된 소요 시간45.48초입니다.
GPU 호출은 없습니다. 실행 근거는 `validation/unified_review_execution_20261029.json`,
휴대용 재생본은 `demo/artifacts/unified_review_20261029.replay.json`입니다.

수정 후 실행은 브라우저 연결이 끊겨 동일 승인 레코드의 실행 백엔드를 명시적으로
호출했고, 완료 후 실제 브라우저의 Recent reviews/Evidence에서 다시 확인했습니다.
끊김 없는 브라우저 전체 실행을 촬영했다고 주장하지 않습니다.

## 사용자 순서

1. **New review**를 누릅니다. 등록 예제를 선택하거나 전체 기준 FASTA를 업로드합니다.
   Download example FASTA로 실제 지원 입력을 받을 수 있습니다.
2. 요청을 적습니다. 예: `Review A32V for sequence plausibility.`
3. **Validate input**으로 서열·번호·보호 잔기를 검사합니다. 이 단계는 호출하지 않습니다.
   `S108A`는 거부되고, `G32V`는 기준 잔기 불일치로 거부됩니다.
4. 파일 정체성, 전체 기준 위치, 체크포인트, 호출 상한과 미확인 비용을 확인합니다.
   허용과 비용 확인을 각각 체크한 후 **Execute approved review**를 눌러야 실제 실행됩니다.
5. 완료/부분 완료/실패를 구분해 표시합니다. 반환된 근거는 같은 앱에서
   **Overview / Candidates / Structure / Agent Trace / Evidence**로 검토합니다.
6. **Recent reviews**에서 다시 열면 저장된 결과만 읽습니다. 재실행하지 않습니다.
   **New request from this input**은 원래 실행을 재시도하지 않고 별도 미실행 요청을 만들며
   다시 허용·비용 확인·실행 승인을 요구합니다.

## 지원 파일과 과학적 한계

- 실행 가능한 서열은 등록된 공개 Lipase A 전체212개 기준 서열입니다. 파일 헤더/줄바꿈은
  달라도 정규화한 서열이 정확히 일치해야 합니다. 파일 원본 해시도 별도로 보존합니다.
- 181개 mature 서열, 다른 단백질과 잘못된 기준 잔기는 실행 전에 거부합니다. 업로드한 파일을
  몰래 등록 예제로 바꿔 실행하지 않습니다.
- 선택적 구조 업로드는 고정된 공개1ISP mmCIF와 정확히 일치해야 합니다. 다른 좌표/PDB변환은
  지원한다고 표시하지 않습니다. 구조 파일이 없으면 기존 검증된 공개 기준 구조를 사용합니다.
- 변이 요청은 해당 위치의19개 non-WT 대안을 하나의 공통 정책으로 검토합니다. optional
  구조·Atlas 근거가 순위를 바꾸지 않습니다. ESM 점수는 내열성·활성·용해도·Tm 실험값이 아닙니다.
- Structure에서 A32는 원자가 없어 서열 문맥만 표시합니다. S108은 author77에 대응합니다.
  기준 구조, 저장된 변이체 예측, 좌표 번호 대응과 원자 기하 검증을 구분합니다.

## 중복 실행·중단·예산

호스트 소유 SQLite 기록이 검증 입력을 고정하고, 실행 전에 한 번만 원자적으로
`validated → running`을 바꿉니다. 새로고침·다른 브라우저·결과 탐색으로 같은 기록을 다시
실행할 수 없습니다. 중단된 running 상태도 자동 재시도하지 않습니다.

기본 로컬 허용량은3건이고 요청별 Meta 상한은4회입니다. 새로고침이나 서버 재시작으로
허용량을 초기화하지 않습니다. 처음 준비 단계에서 멈춘 기록도 보수적으로 한 건을
사용한 것으로 남깁니다. 추가 허용량은 운영자가 별도 승인된 예산 배치로 명시적으로
구성해야 하며, 이력을 삭제해 비용 제한을 우회하지 않습니다. 호출 상한/로컬 예약은
실제 제공자 청구액을 보장하지 않습니다. 실제 비용은 계속 unknown입니다.

첫 준비 실패는 승인된 Atlas 도구가 추가된 카탈로그를 옛 기본 호스트가 거부한 문제였습니다.
그 기록과 Meta 예약0건을 보존했습니다. 기본 검토 호스트는 현재 알려진 선택적 Atlas의
존재를 허용하되 Meta에는 기본 검증/점수 도구만 제공합니다. 알 수 없는 도구·중복 도구는
계속 거부합니다. 기존 MCP의 서버 가드와 평가 정답 분리는 유지합니다.
