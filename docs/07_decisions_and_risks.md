# 07. Decisions and remaining risks

| Decision | Rationale | Revisit only when |
|---|---|---|
| Indie / Push the Frontier | One developer, scientific tool execution | Working implementation supports a more honest alternate framing |
| MCP-first core | Reuse in a verified host and make scientific tools inspectable | Protocol adds unacceptable complexity without actual reuse |
| Controlled Meta host as reference | Bounded costs, output contracts and label isolation | Muse Code demonstrates equivalent required controls |
| Streamlit optional | Show value without building a whole platform | Final access requirements demand a hosted surface |
| Keep v2 biology | Avoid phenotype and residue-numbering overclaims | New evidence explicitly passes the relevant gate |
| Atlas optional context | No verified necessity for baseline scoring | A preregistered test shows real benefit |
| One common rank policy | Comparable ESM scores | A new policy is frozen and evaluated, not retrospectively tuned |
| No prize-driven model proliferation | Finish actual work first | Core reliable, explicit budget and time remain |

Primary unresolved risks: participant eligibility; pre-event design/helper reuse; final demo-access
requirements; actual Meta model/API rights; Muse Code usage billing; partner-credit restrictions;
Atlas endpoint/provider version; original-versus-curated assay audit; WT/uncertainty definition;
PDB atom mapping; real ESM environment; held-out leakage and public-benchmark memorization.

`compliance/rules_snapshot.json` separates observed guide text, interpretation and pending questions.
`submission/evidence_matrix.json` begins with missing proof, not successful results.
Neither an approved application nor a passed unit test resolves all submission risks.
