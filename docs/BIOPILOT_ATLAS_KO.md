# BioPilot Bench v3: MCP 중심 구성과 해커톤 제출 준비

수정일: 2026-10-27

## 이번 업데이트의 핵심

**대규모 웹사이트보다 Meta 모델이 실제 과학 도구를 실행하는 MCP 구성을 우선합니다.**
시연 화면은 Streamlit으로 간단히 붙일 수 있습니다. 별도 설치형 프로그램은 이 계획의 필수 항목이 아닙니다.
다만 심사위원의 실행·접근 방식은 최종 제출 양식에서 확인해야 합니다.

```text
User -> Meta host -> BioPilot MCP server -> scientific core -> ESM / reference evidence
                           |                     |
                           +--- run records -----+--> optional Streamlit viewer

Frozen predictions -> isolated offline evaluator (labels are not exposed to the agent)
```

Muse Code는 기존 MCP 호스트로 사용할 수 있는 후보입니다. 실제 모델, 버전, 권한과 비용 조건을 확인한 뒤 연결합니다.
통제가 어려우면 작은 Python 호스트에서 Meta API와 MCP를 연결합니다. 두 경로를 모두 크게 개발할 필요는 없습니다.

## 테마와 심사 기준

기본 선택은 **Indie Developer / Push the Frontier**입니다.
Build for Your World에도 맞지만, 실제 연구 도구를 실행하는 기능을 중심으로 설명합니다.
새로운 효소를 발견했다거나 실험을 대체한다고 과장하지 않습니다.

| 항목 | 비중 | 준비할 증거 |
|---|---:|---|
| Impact | 30% | 연구 작업의 문제와 측정된 효과 |
| Meta AI Tooling | 25% | Meta의 실제 도구 선택과 MCP 실행 기록 |
| Technical Depth & Execution | 20% | 생물학적 제약, 재현성, 오류 처리 |
| Demo | 25% | 입력부터 결과까지 작동하는 3분 영상 |

위 기준은 대화에서 직접 확인한 공식 안내의 내용입니다. 이번 턴에 최종 규칙을 새로 인증한 것은 아닙니다. [S21]

## 3분 시연 순서

| 구간 | 보여줄 내용 |
|---|---|
| 0:00-0:20 | 문제와 결과물을 설명합니다. |
| 0:20-0:45 | 요청과 생물학적 제약을 입력합니다. |
| 0:45-1:20 | Meta의 MCP 호출과 실제 ESM 결과를 보여줍니다. |
| 1:20-1:50 | 제약 변경이나 오류에 대응합니다. |
| 1:50-2:25 | 후보, 근거, 미확인 사항을 보여줍니다. |
| 2:25-2:45 | 실제 비교 결과나 미측정 한계를 설명합니다. |
| 2:45-3:00 | 대회 중 새로 만든 부분과 재현 방법을 설명합니다. |

영문 대본은 `demo/NARRATION_EN.md`에 있습니다. 숫자를 임의로 채우지 말고 실제 결과를 반영하세요.
저장된 실행을 재생하면 REPLAY로 표시합니다. 영상의 실제 길이와 음성은 녹화 후 확인해야 합니다.

## 기존 생물학적 검토를 유지합니다

## 1. 제품의 범위를 바로잡았습니다

BioPilot Bench는 공개 효소의 단일 변이 후보를 ESM 점수와 서열·구조 근거로 검토하는 연구 보조 도구입니다. 내열성 향상이나 기능 유지를 보장하는 효소 최적화 시스템으로 소개하지 않습니다.

사용자가 자연어 목표를 바꾼다고 ESM이 활성·용해도·내열성을 각각 예측하는 모델이 되는 것은 아닙니다. 기본 버전은 `sequence_plausibility_review`와 `lipase_T50_hypothesis_review`만 지원하도록 제한했습니다. 두 번째 항목도 T50에 관한 가설 검토이며, 보정된 온도 예측이 아닙니다.

## 2. 서열 대응은 확인하고, 좌표 대응은 분리했습니다

ProteinGym의 212개 기준 서열과 RCSB에 등록된 1ISP의 181개 서열을 직접 비교했습니다. 181개 서열 전체가 기준 서열의 32~212번과 정확히 일치합니다. 출처와 로컬 서열 해시는 `reference/`에 있습니다. [S11, S19]

| 성숙 서열 번호 | 전체 기준 서열 번호 | 기본 처리 |
|---|---|---|
| Ser77 | Ser108 | 대화형 후보 생성에서 보호합니다. |
| Asp133 | Asp164 | 대화형 후보 생성에서 보호합니다. |
| His156 | His187 | 대화형 후보 생성에서 보호합니다. |

촉매 잔기는 원논문의 주석과 대조했습니다. 이 세 위치를 보존해도 다른 위치의 변이 때문에 활성이 달라질 수 있으므로, 기능 유지가 입증됐다고 표현하지 않습니다. [S17]

**이 대응표는 서열 번호에 대한 확인입니다. PDB의 저자 번호나 실제 원자 좌표에 대한 확인은 아닙니다.** 원자 좌표 파일을 가져오지 못했기 때문에 관련 필드는 `null`로 남겼습니다. 좌표가 확인되지 않은 상태에서는 거리·접촉·구조적 변화 계산을 진행하지 못하게 했습니다. 결측값을 0이나 임의의 좌표로 채우지 않습니다.

## 3. T50와 평가 기준을 구분했습니다

대상 논문의 T50는 20분 열처리 뒤 잔존 활성을 이용한 곡선에서 구한 시험 조건별 지표입니다. 녹는점 Tm, 접힘 자유에너지, 촉매 효율이나 산업 공정 수명과 동일하지 않습니다. [S17]

ProteinGym 메타데이터의 이진 분류는 중앙값을 기준으로 합니다. 이를 야생형보다 개선된 변이라고 해석하지 않습니다. 야생형 대비 개선을 판단하려면 같은 조건의 야생형 측정값, 변이 측정값, 단위와 오차 기준을 별도로 확인해야 합니다. 확인 전에는 개선 여부를 ‘미확인’으로 표시합니다. [S11]

원논문의 3,439개 전체 단일 변이 라이브러리와 ProteinGym 메타데이터의 2,172개 변이는 같은 평가 집합이 아닙니다. 차이가 생긴 이유를 추정하지 않고 원자료와 가공 자료를 대조하도록 했습니다. 실제 변이별 측정값은 이 ZIP에 넣지 않았습니다. [S11, S17]


## 개발 순서와 확인 범위

`H0 -> B0 -> C1 -> C2 -> B1 -> C3 -> C4 -> C5 -> E1 -> S1`의 순서로 진행합니다.
자세한 파일 경로와 테스트는 새 구현 계획서에 있습니다.
실험 정답과 평가 결과를 MCP로 예측 에이전트에게 제공하지 않습니다.

동일한 ESM 점수와 후보를 쓰면 고정 파이프라인과 에이전트의 순위가 같을 수 있습니다.
이때는 작업 완료율, 사람의 개입, 근거 누락, 시간과 비용을 별도로 비교합니다.

`docs/VALIDATION.md`에 실제 검사 결과와 미수행 항목을 구분했습니다.
오프라인 테스트 통과를 Meta 연동, ESM 성능, 동영상 검증과 혼동하지 마세요.
