# 작은 워크플로 비교를 해석하는 방법 — 2026-10-28

이번 비교의 단위는 **입력 검토 과제(policy intake)**입니다. ESM 계산을 끝낸
단백질 검토, 실험 성능 평가, 연구자의 전체 작업 시간과 구분합니다.
프로토콜은 결과를 실행하기 전에 고정합니다. 처음 로컬 guard만 측정한 v1은
`evaluation/workflow_protocol.json`이며, 별도 승인된 실제 Meta 호출은 새 버전
`evaluation/workflow_protocol_meta_v2.json`에 고정해 수행했습니다. v1은 수정하지 않았습니다.

동일하게 비교할 여섯 과제는 정상 A32V, mature 번호 입력, 보호 잔기 S108A,
WT 불일치 G32V, 지원하지 않는 활성 목적, 미검증 원자 좌표 요청입니다.
올바른 차단이나 미제공 응답도 해당 과제의 정답이 될 수 있습니다.

## 현재 측정의 범위

v1 자동 고정 방식은 실제 등록된 제품 guard를 호출했고 6개 중 6개를 올바르게
처리했습니다. 최초 영수증 `validation/workflow_policy_baseline_20261028.json`의
로컬 실행 시간은 약 11.1 ms이며 Meta·수동 관측치는 없습니다. 이 기록은 보존합니다.

이후 v2의 같은 여섯 과제에 대해 실제 Meta 관측치를 수집했습니다. 현재 비교 결과는
`validation/workflow_comparison_20261028.json`, 시도 이력과 한계는
`validation/workflow_meta_arm_success_20261028.json`에 있습니다.

| 방식 | 현재 관측 | 올바른 처리 | 누락 | 기록된 실행 시간 |
|---|---|---|---|---|
| 고정 guard (`actual_local_policy`) | 6개 | 6/6 | 0개 | 약 7.02 ms |
| Meta (`actual_meta`) | 6개 | 5/6 | 0개 | 약 12.41초 |
| 수동 | `not_run` | 미측정 | 6개 | 미측정 |

이 표는 v2 비교 아티팩트의 `methods` 값입니다. 실행 시간은 사람의 작업 시간이
아니며, 연구자의 시간 절감이나 비용 이득을 뜻하지 않습니다. 사용자가 수동 방식의
수행을 생략했으므로 여섯 과제×세 방법의 전체 분모에서 수동 6개 누락을 유지합니다.
`matched_scenario_count`는 0, `workflow_gain_supported`는 false입니다. 사람 시간·수정
횟수·미확인 비용을 0으로 채우거나 실패 과제를 빼고 성공률을 다시 계산하지 않습니다.

Meta의 한 오답은 `WTmismatchG32V`입니다. 모델은 accepted/validated로 응답했지만
제품 guard는 참조 잔기의 불일치를 확인해 rejected/wt_mismatch로 차단했습니다.
두 판단은 같은 관측치에 별도로 보존합니다. 모델이 frame·목적·보호 위치를 검토했어도
참조 WT 잔기 일치 여부를 확인하지 않았다는 사례이며, 결정적 guard가 필요한 근거입니다.

이 Meta 측정은 등록된 규칙을 문맥으로 제공하고 여섯 reason code 중 하나를 고르는
좁은 과제입니다. 규칙 발견, 독립적인 생물학 판단, ESM 검토 완료나 T50 예측 능력을
측정하지 않습니다. 최초 6회 호출은 출력 길이 제한으로 모두 실패했고 보존되어 있습니다.
후속 1회 탐색과 5회 실행을 포함한 실제 provider 호출은 총 12회였습니다. 로컬 예약액은
$0.60이며 모든 응답의 청구 금액은 null이어서 실제 비용은 unknown입니다. 이 측정에서
ESM 추론·GPU 작업·외부 서열 업로드는 없었습니다. 원래 Meta/MCP/ESM 실행 영수증은
별도의 작동 증거이며 이 작은 비교의 Meta 관측치로 끼워 넣지 않습니다.

## 추가 관측치를 수집할 때

1. 각 방법에 같은 공개 참조, 입력, 번호 체계, 보호 잔기와 허용 도구를 제공합니다.
   평가 정답·생물학적 결과·비공개 자료는 제공하지 않습니다.
2. 수동 방식은 사람이 명시된 가드와 근거를 사용해 응답을 완성하도록 하고,
   실제 시작·종료 시각과 수정 횟수를 기록합니다. 작업 순서에 따른 학습 효과도 적습니다.
3. Meta 방식은 허용 도구와 제한을 고정한 구체적 실행 계획을 준비합니다. 새 실제
   provider 호출은 호출 수·출력 한도·예산을 제시하고 별도 명시 승인 뒤에 수행합니다.
   현재 프로토콜의 provider 허용값을 조용히 바꾸지 말고 새 버전으로 동결합니다.
4. trace로 실제 도구 호출과 응답을 보존하고, 짧은 공개 이유를 사용합니다.
   비공개 사고 과정은 수집하지 않습니다. 올바른 차단과 처리 실패를 구분합니다.
5. 같은 과제를 수행한 관측치만 비교합니다. 작은 시범 측정이라는 한계를 붙이고
   결과가 같거나 Meta 방식이 더 느린 경우도 그대로 보고합니다.

제품 화면의 **Offline input check**는 실제 로컬 guard 상호작용입니다. 그 화면에서
S108A를 차단했다고 해서 Meta가 적응적으로 판단한 증거가 생기지는 않습니다.
녹화에서도 저장된 Meta trace 재생과 새 로컬 검사를 구분합니다.
